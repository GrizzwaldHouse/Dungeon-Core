# Dungeon Core Crawler — visual direction review

**Review artifact:** [FIGMA_DESIGN_BOARD.svg](FIGMA_DESIGN_BOARD.svg)
**Owner:** UI/UX design agent
**Status:** Import-ready design direction; the Figma cloud board has not been created because the connected Chrome session opens Figma's sign-in page and no Figma creation tool is available in this session.

## What the board shows

1. A five-floor story arc: the Breach tutorial; sequential Keeper and Hexer trials; finite resource waves; an ordered rune/trap/guardian trial; and the Shifting Core Warden finale.
2. Desktop and phone game HUD proposals using the current dark stone, mint, and gold visual language.
3. A danger language with a patterned amber area, 1.5-second warning, and audio cue. Color alone must never be the only warning.
4. Status, health, objective, room code, recovery, and action placement that stays visible during combat.

## Current source versus direction

The current client source contains a full-screen Three.js viewport, room form and code, party panel, server-driven entity rendering, status channel, touch controls, and responsive CSS. The board's boss health layout, exact floor identities, compact mobile action grouping, and multi-sensory warning treatment are **proposals**. Floor-two through floor-five modules and server transitions are committed as an integration candidate; the board is not evidence that all five floors are playable.

## Decisions for Marcus

- Should the atmosphere lean toward storybook wonder, ominous combat, or a floor-by-floor transition between them?
- On phones, should six actions remain permanently visible or collapse situational actions under one large context button? Preserve accessible labels either way.
- Which final boss silhouette should lead portfolio imagery: fractured stone knight, living portal, or crystalline creature?
- Should personal rewards emphasize each player's contribution in the live HUD, or appear only at floor completion?
