## OWNER-002: cross-client pickup

Two human clients completed Floor One and entered recovery. Both saw the same `rest-supply` item ID with no claims. Host collected it. Peer received `item:collected` and a `room:snapshot` whose `claimedBy` contained only Host. Host received the same claim list. Host inventory rose to one healing charge, while Peer remained at zero. A second Host claim returned `ALREADY_CLAIMED`. Peer then approached the same item and claimed it once. Both player IDs appeared in `claimedBy`, Peer inventory rose to one, and a repeat Peer claim returned `ALREADY_CLAIMED`.

**Finding:** The owner's observation that the item remains for Player 1 after Player 2 collects it matches the current personal-claim contract. It is not evidence of a missed server broadcast. `client/render.js` hides a marker only when `claimedBy` contains the local player ID. The current presentation does not clearly state that a shared world cache gives one reward to each eligible explorer.

**Proposal for lead:** Keep personal claims unless Marcus explicitly changes the loot contract. Add UI copy such as "Each explorer can claim this cache once" and a distinct claimed-by-you state or contextual affordance. Verify the same claim list and separate inventory counts in two actual browsers or a laptop plus phone before closing OWNER-002. If shared one-time loot is desired, change server entitlement and UI together, with a migration of this test's expected outcome.

## OWNER-003: background reconnect

The server's configured grace was shortened to its valid minimum of 1,000 ms for the test. During a running Floor One room, Peer disconnected and a new independent socket rejoined inside grace using its room code and reconnect token. The player ID and room phase were preserved, the server returned a different token, and the old token was rejected. In a separate room, a reconnect after the server removed Peer at grace expiry returned `INVALID_REJOIN`; Host remained connected and the room remained `RUNNING`.

**Finding:** The basic server rejoin and expiry contract behaved as configured on local Socket.IO. This does not reproduce the owner's intermittent iPhone failure. It also does not establish what happens when Safari suspends a tab without a clean WebSocket close, when Socket.IO automatically recovers a transport, on a public host, or after a completed run. Production grace is 30 seconds; the test used 1 second to exercise the same server branch promptly.

**Proposal for lead:** Add client diagnostics that record the lifecycle stage and safe error code without logging reconnect tokens: `disconnect`, `connect`, `room:rejoin` attempt, acknowledgement, token rotation, snapshot acceptance, and any `INVALID_REJOIN` or timeout. On failure, show a clear expired-session action that returns to the name and room form. Test a physical iPhone at under 30 seconds, near 30 seconds, and over 30 seconds, both mid-run and on the results screen. Do not increase grace solely from this local pass; measure room retention and capacity first.
