# Multiplayer bug tracking

Use the [canonical defect ledger](../defects/README.md) for verified local defects. Once a GitHub repository is connected, the GitHub `Multiplayer bug` issue form can collect shared reports; link the issue to its local record after reproducing it. For private local reproduction notes, copy the checklist below into an issue draft, then remove any secrets before sharing.

- Build/commit and browser/OS per player:
- Player count and room phase:
- Numbered reproduction steps, including action order and disconnect timing:
- Expected versus actual behavior:
- Server tick and room revision at first divergence:
- Which clients disagree, and what each displayed:
- Sanitized server/client error excerpt:
- Reproduction rate and workaround:

Never record live room codes or reconnect credentials. Use fake values in reports.
